# 数据流

系统存在 4 条独立的数据路径,分别对应不同的交互场景。

## Path A: Web面板 → Agent (场景对话)

**流程**: 用户通过外部通道发送消息 → FastAPI 启动一次性 agent 进程 → 直接返回结果。

```
外部用户 → HTTP POST /api/scenes/{id}/chat
         ↓
FastAPI (web/main.py:_agent_process_message)
         ↓
subprocess.run(["python", "agent_runtime.py"], input=JSON-RPC task)
         ↓
agent_runtime.py 读取 stdin → handle_request("task")
         ↓
AgentRunner → AgentLoop.run() → ReAct 循环
         ↓
结果写入 stdout → FastAPI 解析最后一行 JSON
         ↓
回复给用户 + 记录到 scene_router 历史
```

**特点**: 一次性进程,用完即销毁。与环境变量中的 API key 绑定。

## Path B: Agent间任务分发

**流程**: Agent A 通过 `dispatch_task` 工具 → 写文件到队列 → Rust 读取 → JSON-RPC 转发给 Agent B → 回复写回消息总线。

```
Agent A (dispatch_task 工具)
         ↓ 写入文件
agents/dispatch_queue/dispatch_{target}_{ns}.json
         ↓ Rust 轮询 (每 5s)
main.rs:check_and_process_dispatches()
         ↓ 解析 JSON,获取 target_id + prompt
registry.dispatch_message(target_id, "task", params)
         ↓ JSON-RPC call
Agent B (agent_runtime.py)
         ↓ 处理完成
Rust 读取响应 → 写 chat/group.jsonl (消息总线)
```

**关键文件**:
- `agents/dispatch_queue/*.json` — 待分发任务
- `agents/dispatch_messages/{id}.msg` — 分发记录日志

## Path C: 聊天群组

**流程**: Admin 发消息到群组 → 心跳检查未读 → 按优先级评分 → agent 处理。

```
Admin → REST API → chat/groups.json → messages.jsonl
         ↓
Agent heartbeat (300s 周期)
         ↓
chat_reader.get_unread_messages(agent_id)
         ↓
每 条消 息评分: @提及 +100, @all +80, admin +50, leader +30
         ↓
score >= 10 才处理,按分数降序
         ↓
AgentLoop.run() 处理
         ↓
mark_as_read() 标记已读
```

## Path D: 邮箱

**流程**: Agent A 通过 `send_message` 工具写 inbox → Agent B 心跳读取 → 处理 → 标记已读。

```
Agent A (send_message 工具)
         ↓
agents/mailbox/{target_id}/inbox.jsonl
         ↓
Agent B 心跳 (heartbeat.py)
         ↓
read_inbox(agent_id) → 过滤 unread
         ↓
for each unread: _execute_task(prompt)
         ↓
mark_read(agent_id, idx)
```
