# 记忆系统

每个 agent 在启动时创建自己的记忆目录：

```
agents/
└── memory/
    └── {agent_id}/
        ├── MEMORY.md          # 长期记忆(LLM 可读写)
        ├── PROFILE.md         # 用户画像(per-user)
        ├── history.jsonl       # 完整对话历史
        ├── .dream_cursor       # 上次 Dream 位置
        └── users/
            └── {user_hash}/
                └── PROFILE.md
```

## MEMORY.md

长期记忆文件，供 LLM 在 system prompt 中读取。由 Dream 过程维护。

格式示例：

```markdown
# {agent_id} 的记忆

## 关键事实
- 用户张三偏好技术文档
- 团队成员: Alice(leader), Bob(engineer)
```

## Dream 过程

定义于 `py-agent/dream.py`。

**触发条件**：
- 每 30 分钟
- 积累 ≥3 条未处理记录

**流程**：

```
1. 读取 .dream_cursor 获取上次处理位置
2. 从 history.jsonl 读取新条目
3. 构建 LLM prompt，要求分析并提取:
   - 决策和理由
   - 关于用户的事实
   - 偏好和模式
   - 重要事件
4. LLM 返回结构化分析结果
5. AgentLoop 执行手术式编辑:
   - 仅允许 read_file + edit_file 工具
   - 对 MEMORY.md 进行精确的插入/修改/删除
6. 更新 .dream_cursor 到最新位置
7. 执行 git commit 记录变更
```

**关键设计**：AgentLoop 执行编辑而不是直接写文件。这样编辑过程受工具权限和 ReAct 循环约束，避免 LLM 一次生成破坏性内容。

## 历史压缩 (auto-compact)

`py-agent/auto_compact.py`：

- 当 `history.jsonl` 超过阈值（默认 500 条），触发压缩
- LLM 将早期消息合并为摘要
- 原始消息归档到 `history.jsonl.bak`
- 压缩后消息数减少约 70%

## Git 版本管理

记忆目录是一个 Git 仓库：

```
cd agents/memory/{agent_id}
git log --oneline
```

每次 Dream 编辑后自动 commit。支持回滚：

```
git revert HEAD
```

## Per-User 记忆

每个与 agent 对话的用户有独立 PROFILE.md：

```
users/{sha256(user_id)[:8]}/PROFILE.md
```

Dream 过程针对每个用户的对话运行 `run_user_dream()`，提取该用户的偏好、习惯、背景等信息。

## 数据流

```
用户对话 → history.jsonl 追加
     ↓ (定时触发)
Dream 分析历史
     ↓
提取事实 → 编辑 MEMORY.md / PROFILE.md
     ↓
git commit
     ↓
下次构建 system prompt 时读取最新 MEMORY.md
```
