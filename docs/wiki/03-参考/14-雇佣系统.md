# 雇佣系统

雇佣系统允许用户通过对话新增 agent。整个过程端到端自动化。

## 流程概述

```
用户调用 hire_agent 工具
       ↓
写 pending JSON 到 hire_requests/
       ↓
Rust 守护进程轮询发现
       ↓
Rust 通过 stdin 提示用户确认
       ↓
用户输入 y 批准
       ↓
Rust 更新 config.toml + 创建 agent 目录
       ↓
spawn 新 agent 子进程
       ↓
完成，写入 chat 消息通知
```

## 详细步骤

### 1. 用户发送 hire 请求

用户通过聊天调用 `hire_agent` 工具：

```json
{
  "name": "新助手",
  "role": "employee",
  "scene": "default",
  "interpreter": "python",
  "script": "py-agent/agent_runtime.py"
}
```

### 2. 写入 pending 目录

工具将请求写入 `agents/hire_requests/pending/`：

```json
{
  "id": "新助手",
  "name": "新助手",
  "role": "employee",
  "scene": "default",
  "interpreter": "python",
  "script": "py-agent/agent_runtime.py",
  "requester": "user_xxx",
  "timestamp": "2025-01-15T10:30:00Z"
}
```

### 3. Rust 轮询

Rust 主循环每 5s 检查 `process_pending_hires()`。

### 4. 用户确认

Rust 通过控制台 stdout 打印：

```
[新助手] requests to join as employee. Approve? (y/N)
```

用户输入 `y` → Rust 将文件移动到 `approved/` 目录。

### 5. 处理批准

Rust 主循环每 5s 调用 `process_hire_requests()`：

```
1. 读取 approved/*.json
2. 追加 [[agents]] 到 config.toml
3. 创建 agents/memory/{id}/ 目录
4. 写 profile.json
5. 调用 registry.start_one() spawn 进程
6. 删除已处理的请求文件
```

### 6. 通知

新 agent 创建后，系统消息写入消息总线：

```
System: 新助手 (employee) 已加入场景 default
```

### 7. 查看

新 agent 出现在：
- `agents/config.toml` 的 `[[agents]]` 段
- Web 面板的 Agent 列表
- 场景成员列表 (roster.json)

## 目录结构变更

```
agents/
├── config.toml          # 新增 [[agents]] 条目
└── memory/
    └── {new_id}/
        ├── MEMORY.md    # 初始为空
        ├── profile.json # 角色信息
        └── history.jsonl # 初始为空
```
