# 关键设计决策

CocoCat 在开发过程中做了一系列架构权衡。以下是关键决策及其背后的理由。

## 决策 1：文件系统作为消息总线

**选择**：文件系统（JSON 文件 + JSONL）+ Rust 轮询

**替代方案**：Redis Pub/Sub、RabbitMQ、gRPC stream

**理由**：
- **零依赖**：无需安装和运维消息队列系统
- **可调试性**：任何人都可以 `cat agents/dispatch_queue/*.json` 查看当前 pending 的任务
- **持久化天然**：JSONL 文件就是完整的消息历史
- **简单可靠**：文件系统比分布式消息队列更不容易出故障

**代价**：
- 轮询有延迟（5s 间隔）
- 不适合高频消息场景（>100 msg/s）
- 不适用于分布式部署（多台机器共享 NFS 时有竞态风险）

## 决策 2：轮询 vs 推送

**选择**：Rust 层轮询（health check 15s，dispatch 5s，hire 5s）

**替代方案**：Python Agent 主动推送状态给 Rust

**理由**：
- **Rust 是调度者，不是被调度者**：Rust 作为核心引擎，保持控制权
- **简化 Agent 逻辑**：Agent 不需要知道 Rust 的存在，只处理 stdin/stdout JSON-RPC
- **容错**：Agent 崩溃后 Rust 自动检测并重启，不需要 Agent 关心恢复

**代价**：
- 轮询间隔内的延迟
- 频繁的 `try_wait()` 系统调用

## 决策 3：JSON-RPC over stdin/stdout

**选择**：子进程的 stdin/stdout 传递 JSON-RPC 2.0 消息

**替代方案**：HTTP (localhost)、Unix Domain Socket、命名管道

**理由**：
- **最简 IPC**：不需要网络栈，不需要端口管理
- **进程天然绑定**：stdin/stdout 的生命周期与子进程绑定，子进程死掉 IPC 自动断开
- **跨平台**：Windows 和 Linux 行为一致
- **无需序列化框架**：JSON 文本协议，两端都可直接 readline/writeline

**代价**：
- 不适合传输二进制数据
- 单向通信（Rust→Agent 通过 stdin，Agent→Rust 通过 stdout，不能反向）
- 子进程 stdout 不能混入调试输出（调试输出需写 stderr）

## 决策 4：单 Rust 进程 vs 分布式

**选择**：单 Rust 守护进程管理所有 Agent

**替代方案**：每个 Agent 独立管理、Kubernetes 编排

**理由**：
- **简化部署**：一个二进制 = 完整的核心引擎
- **进程内状态共享**：AgentRegistry 的 HashMap 即服务发现
- **适合单机场景**：Agent 数量通常 < 50，单机足够

**代价**：
- 单点故障（Rust 进程崩溃 = 所有 Agent 失去管理）
- 水平扩展受限（不能跨机器分布 Agent）
- Rust 进程重启需要重连所有 Agent

## 决策 5：Python 子进程 per Agent vs 单进程多线程

**选择**：每个 Agent 一个独立的 Python 子进程

**替代方案**：单个 Python 进程内用多线程/协程管理多个 Agent

**理由**：
- **故障隔离**：一个 Agent 的崩溃不会影响其他 Agent
- **资源隔离**：每个 Agent 有独立的 Python 运行时、内存、文件句柄
- **独立配置**：每个 Agent 可有不同环境变量（如不同的 API key）
- **Rust 管理**：Rust 作为进程管理器，可以检测、重启单个 Agent

**代价**：
- 每个 Agent 约 30-50MB 内存开销
- 进程启动开销（首次 task 请求时初始化）

## 其他决策摘要

| 决策 | 选择 | 理由 |
|------|------|------|
| 工具注册 | 代码注册 vs 声明式 YAML | 类型安全，IDE 支持，易于重构 |
| 对话历史 | JSONL vs SQLite | 追加写性能好，易于 tail/管道处理 |
| 频道路由 | EntryManager 线程 vs 独立进程 | 简化部署，共享内存 state |
| 记忆版本 | Git vs 自定义快照 | 零依赖，功能丰富，熟悉的操作 |
| 知识库索引 | 自动 LLM 生成 vs 手动维护 | 减少维护成本，但需要 LLM 调用 |
| 权限配置 | 环境变量 vs per-agent 配置 | 简化操作，大部分场景权限统一 |
