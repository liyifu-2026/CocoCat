沙箱分配策略：一个沙箱一个 Agent？还是共享？

CubeSandbox 冷启动 < 60ms，但每次创建仍有开销

A

一个沙箱 = 一个 Sub-Agent（即用即毁）

Main AI 每次 dispatch_task → 建一个沙箱 → Agent 执行 → 销毁。和现在 run_once 模式一致。

优点

  • 隔离最彻底，任务间互不影响
  • 实现简单，复用现有 run_once

缺点

  • 多任务并发可能占多个沙箱
  • 沙箱间无法共享状态
B

一个沙箱 = 一个会话（Main AI 的整个 DAG 执行过程）

用户发消息 → 创建一个沙箱 → 该轮所有 Sub-Agent 复用同一个沙箱 → 用户回复后销毁。

优点

  • 减少沙箱创建开销
  • Sub-Agent 间可共享文件上下文

缺点

  • 一个 sub-agent 出错可能污染沙箱
  • 沙箱生命周期管理更复杂
