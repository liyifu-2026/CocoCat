CocoCat Agent 架构现状

Main AI 和 Sub-Agent 分别跑在什么上面

两条路径

路径 1：Main AI（用户聊天）
POST /api/chat
  → SandboxProvider.run_once(prompt, agent_id="main", tools=...)
      → LocalExecutor.run()
        → Agent.run()   ← 宿主机
          工具: define_dag, dispatch_task, 
                pin, recall, read_file...
          ❌ 没有 bash
路径 2：Sub-Agent（被 dispatch_task 触发）
Main AI 调 dispatch_task → 发送任务
  → SubAgentExecutor.dispatch(task, agent_id)
    → if sandbox_provider:
        SandboxProvider.run_once(task, tools=...)
          → LocalExecutor.run()
            → Agent.run()   ← 宿主机
              工具: bash, write_file, browser,
                    read_file, glob, grep, ...

关键事实

SandboxProvider 当前默认用 LocalExecutor

SandboxProvider(executor=None) → 自动创建 LocalExecutor()，Agent 跑在宿主机进程内。

CubeSandboxExecutor 已存在但只做 run_code

CubeSandboxExecutor.run() 调用 sbx.run_code(code)，不创建 Agent、不跑 ReAct 循环。它被用作 bash 工具的 sandbox_run 回调，而不是完整的 Agent 执行器。

AgentPool 是启动时从 DB 加载的持久 Agent

_load_agents_from_db() 从 agents 表读取 running 状态的 Agent，创建 Agent 对象加入 AgentPool。SubAgentExecutor 优先用 AgentPool 的闲置 Agent，没有才走 SandboxProvider 创建临时 Agent。

所以 CubeSandbox 应该覆盖哪层？

Main AI 一直跑在宿主机（它没有 bash）。需要隔离的是 Sub-Agent 的工具执行环境。
