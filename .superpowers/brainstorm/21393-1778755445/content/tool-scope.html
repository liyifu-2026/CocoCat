哪些工具要进沙箱？

工具执行位置的选择：宿主机 vs MicroVM

A

只隔离执行工具

bash, write_file, edit_file, browser → 沙箱
read_file, glob, grep, web_search, web_fetch → 宿主机

优点

  • 读操作零延迟
  • 改动最小

缺点

  • 沙箱内文件变更宿主机不可见（需挂载）
B

所有文件/执行工具进沙箱

read_file, write_file, edit_file, bash, glob, grep, browser → 沙箱
web_search, web_fetch, pin, recall → 宿主机

优点

  • 文件系统完全隔离，读写一致

缺点

  • 每次 read_file 都走沙箱 RPC
C

全部进沙箱

所有 26 个工具全在沙箱执行，沙箱挂载宿主机 workspace

优点

  • 完全隔离，不留任何痕迹

缺点

  • pin/recall 等记忆操作也要进沙箱，web 操作也要代理
  • 沙箱模板需额外依赖

性能参考

沙箱内部每次 run_code 调用 ≈ 1-5ms 延迟（本地 CubeSandbox）。
read_file 占 Agent 工具调用比例通常最高。
