Sub-Agent 隔离方案：CubeSandbox 怎么服务 Agent？

三个方向，针对 Sub-Agent 的工具执行环境

A

扩展现状：选择性路由更多工具进沙箱

Agent 循环仍在宿主机。把 write_file、browser、glob 也像 bash 一样通过 sandbox_run 路由进 MicroVM。

优点

  • 改动小（扩展现有模式）
  • Agent 不受 VM 限制

缺点

  • Agent 仍依赖宿主机环境
  • 每个工具单独适配
B

完整 Agent 进 MicroVM

CubeSandboxExecutor 在 VM 内创建完整 Agent 实例，LLM 回连宿主机 Provider，整个 ReAct 循环跑在 VM 里。宿主机只做调度和结果转发。

优点

  • 真正的硬件级隔离
  • Agent 看不到宿主机

缺点

  • VM 模板需装 Python + 依赖
  • 改动量大
C

混合：Agent 宿主机 + 执行工具全进沙箱

Agent 循环复用宿主机的 LLM 连接和 read 工具。所有写操作（bash、write_file、browser）统一进 CubeSandbox。沙箱挂载 workspace 目录。

优点

  • 平衡安全和复杂度
  • one-shot 创建/销毁沙箱

缺点

  • Agent 循环本身不隔离
  • 需要文件系统挂载
