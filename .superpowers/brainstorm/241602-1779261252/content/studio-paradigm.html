关键澄清

🐱
Coco = Main AI（不是吉祥物/副手）
Coco 就是那只橘猫，它是团队的调度核心。它在工作室中有自己的「调度台」，不是到处跑的小动物。
🤖
其他 Agent 有明确角色
比如 kb-agent = 知识库管理员，处理文件、维护知识库。每个 Agent 在工作室中有自己的工位和职责。
🎨
不叫「基建」叫「工作室」
空间布局的灵感来自方舟，但语言用「Studio」。避免游戏术语（干员/基建/制造站），用自然的工作室词汇（工位/调度台/资料架）。

Scene 的重新定义

之前：Scene = 一个「上下文配置」（Context + Agent列表 + Skills + KB）——用户不太理解这个概念。

现在：Scene = 一个独立的工作室。每个工作室有自己的 Agent 团队、自己的资料架、自己的任务流。

SceneRail = 工作室切换器。「开发工作室」「客服工作室」「写作工作室」——每个是一个独立空间，里面有不同的人和资料。

这解释了 Scene 为什么存在：不同的工作，在不同的工作室里做。就像公司里有不同的部门办公室。

对整个页面体系的最终影响

Dashboard → 工作室总览（俯视空间布局，Coco调度台+Agent工位+资料架）
Welcome → 空工作室首次亮灯（Coco 在调度台等你）
Chat → 和工作室对话（从工作室进入，对话后回到工作室）
Agents → 团队成员档案（不是在列表里，而是在工位上看到他们）
Studio（独立页）→ 可能不需要（工作室总览本身就是「Studio」了）
SceneDetail → 被工作室总览吸收（切换 Scene 就是切换工作室视图）
