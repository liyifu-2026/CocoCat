交互体验视角 · 页面增删分析

不只看后端能力，更要看用户心智模型——什么该加、什么该删、什么该合

一、建议删除/合并的页面

🗑

#10 SceneRun —— 建议删除

当前是空 div。在交互模型中，用户从 SceneRail 点击 Scene → 应该直接进入 Chat（带 Scene 上下文）。SceneRun 作为独立页面没有存在的理由——它和「Chat + Scene 上下文」完全重叠。

决策：删除 /scenes/:id/run 路由，SceneRail 点击 Scene → 跳转 /chat?scene=xxx
🔀

#8 ChatHistory —— 建议降级为 Chat 内面板

当前是独立页面 /chat/history。用户浏览历史时需要离开对话上下文。从交互体验来说，历史列表应该是 Chat 页内的一个可展开侧边栏——不打断当前对话流，随手翻阅。

决策：删除 /chat/history 独立路由。在 Chat 页左侧增加「历史会话」可折叠面板。
🔀

#11 SceneDetail —— 建议合并入 Studio

当前 Scene 详情页（Context + Roster + Skills + Knowledge）是独立页。在「创作工作室」隐喻下，查看单个 Scene 的详情 = 在 Studio 画布中聚焦某个 Scene 节点。不需要独立路由。

决策：删除 /scenes/:id 独立路由。Studio 画布中点击 Scene 节点 → 展开详情面板。

二、建议新增的页面（交互体验驱动）

🔎

#21 GlobalSearch —— 全局搜索页

cmdk 已安装但未使用。应该做一个 ⌘K 触发的全局搜索面板：跨 Agent / Scene / KB / 聊天记录 / 记忆 搜索。深度用户的核心操作入口，不依赖鼠标点来点去。

形式：全局浮层面板（非独立路由），⌘K 唤起。后端需聚合搜索 API。
🔔

#22 NotificationCenter —— 通知中心

WebSocket 实时事件（Agent 完成/失败、DAG 结束、新消息）需要一个集中展示的地方。sonner toast 只能处理「此刻」，不能回溯。通知中心 = toast 的收件箱。

形式：顶部铃铛图标 → 下拉面板。SSE/WS 驱动。支持已读/未读 + 点击跳转到相关页面。
📊

#23 SystemStatus —— 系统状态页

自托管部署场景下，用户需要知道系统是否健康。Agent 连接状态、模型 Provider 可用性、Sandbox 状态、磁盘空间。不是核心交互但建立「可信赖」感。

形式：独立页面 /status 或 Dashboard 内的状态卡片。优先级低于核心页面。
