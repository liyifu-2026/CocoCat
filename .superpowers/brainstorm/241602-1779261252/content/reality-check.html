这意味着什么

「工位」概念不成立 — 没有持久的 Agent 等在那个位置上。只有 Coco 调度台和 kb-agent 是固定的。其他「工位」只是当前活跃的沙盒 worker 的临时快照。
「Agent 管理页」需要重新理解 — 当前 Agents 页列出的是 Agent 配置模板（角色定义、tool 权限、system prompt），而不是「在线的团队成员」。它们是 Coco 用来 fork 沙盒 worker 的模板。
Dashboard 应该展示什么？ — 不是「谁在工位上」，而是「当前在发生什么」：Coco 在做什么、哪些沙盒 worker 正在运行、DAG 任务进展、kb-agent 状态。

关键问题：什么场景下需要多 Agent？

你的问题：如果要达成「多 Agent 协作」，什么样的场景会需要？

我的理解：多 Agent 的价值在于 并行执行不同性质的任务。Coco 拆解一个复杂需求（比如「重构整个项目架构」），然后：
  • fork 一个 code-analysis worker 去读代码
  • fork 一个 refactor worker 去改文件
  • fork 一个 test worker 去跑测试
这些 worker 是并行的、临时的——不需要持久存在。真正的「多 Agent」体现在 DAG 的并行执行能力，而不是桌面上坐了一排人。

所以正确的可视化应该是：展示 DAG 的并行任务流——哪些 worker 在并行工作、哪些完成了、哪些在排队——而不是虚拟的「工位」。
