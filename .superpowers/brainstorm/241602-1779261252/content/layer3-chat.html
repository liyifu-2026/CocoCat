Chat 交互的 6 个维度分析

1. 多 Agent 身份展示

多条消息来自不同 Agent 时，如何区分？当前靠颜色头像+名字。但 DAG 场景下一个对话流可能有 3-5 个 Agent 交替发言。

⚠ 需要更强的视觉分层

2. 工具调用的可视化

Agent 调用工具时（read_file, bash, web_search...），当前用暗色代码块展示。但这是核心差异化体验——用户应该能看到 Agent「正在做什么」。

⚠ 工具调用应该更生动

3. 流式输出的质感

当前有 streaming 支持，但流式体验的细腻度（打字机速度、光标、思考状态指示）决定了对话的「生命力」。

✓ 基础流式已有，可打磨

4. 会话上下文面板

右侧面板展示活跃 Agent 和 DAG 进度——方向对，但信息密度和设计质感需要提升。

⚠ 面板存在但可能未充分利用

5. 输入即交互

输入框不只是打字——slash command、@提及 Agent、附件上传、语音输入等都是「多 Agent 协作」场景需要的。

⚠ 输入方式太单一

6. Mermaid 与富内容

已支持 Mermaid 图表渲染，这是一个亮点。但 Markdown 渲染、代码高亮、文件预览等富内容体验可以进一步整合。

✓ 已有基础，扩展空间大
