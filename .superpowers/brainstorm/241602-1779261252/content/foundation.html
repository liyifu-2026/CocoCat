风格校准：需要确认的 4 个选择

1

主色对齐：UI Primary 是否需要和 Logo 猫色统一？

Logo 猫 = #f97316 (纯橘)，UI Primary = #e07b5a (陶土橘)。统一为 #f97316 会更品牌一致，但陶土橘在 UI 中更柔和耐看。

2

猫的 UI 存在感：品牌 IP 在界面中的出现频率？

当前只在 SceneRail 顶部有一个小图标。选项：A) 保持低调 B) 多处点缀（loading 动画、空态插图、error 页） C) 深度角色化（对话中猫猫Agent 有表情反馈）

3

暗色模式策略：主推哪个？

当前明暗都支持。但视觉设计方向 doc 明确写「禁止深色背景」（针对 logo）。UI 的暗色模式是否要保持？主推明色还是双模式平等？

4

字体层级：需要建立更明确的 Type Scale 吗？

当前只有 display（Zen Antique）和 body（Noto Sans SC）两级。代码区用 JetBrains Mono。信息密度提升后可能需要更丰富的字号层级。

三、你可能遗漏的部分（我补充的）

A

空态设计体系

所有页面的空状态（无 Agent、无 Scene、无 KB、无消息）需要有统一的设计语言。当前只有 EmptyState 组件但未在各页面使用。

B

加载态 / 骨架屏体系

LoadingSkeleton + PageSkeleton 已存在但使用不充分。需要定义全局加载策略（页面级/组件级/流式加载）。

C

错误态 + 降级策略

ErrorState/ErrorBoundary 存在但需统一整合。WebSocket 断连、API 超时、权限不足、Agent 执行失败等场景的错误展示。

D

移动端体验

MobileBottomNav 存在但移动端整体未适配。Chat 在手机上是否可用？管理页面是否响应式？需要明确移动端策略。

E

无障碍 (a11y)

键盘导航、屏幕阅读器、焦点管理、颜色对比度。Radix UI 有基础支持但需审核覆盖率。

F

键盘快捷键 + 命令面板

cmdk 已安装但未使用。需要全局 ⌘K 命令面板（页面跳转、Agent 切换、快速操作）。深度用户靠键盘驱动。

G

通知系统

sonner toast 已集成。但缺少：任务完成通知、Agent 状态变更通知、系统级通知中心。WebSocket 事件驱动的通知链路。

H

Settings 信息架构重设计

当前 12 个 Tab 平铺在一个模态框里，信息架构扁平。需要分类重组 + 导航优化。Settings 不应是「垃圾桶」。

I

连接状态 UX

WebSocket 断连/重连的可视化提示。当前可能静默失败。需要连接状态指示器 + 重连动画 + 离线队列提示。

J

功能发现引导

新功能上线后老用户如何发现？需要 feature spotlight / tooltip 引导 / "What's new" 更新日志入口。

K

页面过渡动画

路由切换无过渡动效。Dashboard → Chat → Agents 之间跳转生硬。需要统一的页面转场策略。

L

i18n 覆盖率

现有 zh/en 385+ key 但新增页面需扩展。部分硬编码中文需国际化。需建立翻译 key 命名规范。
