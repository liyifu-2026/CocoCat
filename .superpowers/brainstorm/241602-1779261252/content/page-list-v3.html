补充分析：还有哪些页面可能遗漏？

基于 CocoCat 后端能力反推前端缺失

从后端能力清单反推

后端有、前端无（或前端极弱）的能力
🧠
Memory 记忆系统
后端有完整的记忆体系：Manual 手动记忆 / Dream 自动提取 / Summarize 摘要 / Compile 编译 / FTS5 全文搜索。前端只有 PinnedTab 展示置顶事实，其余完全不可见。
→ 需要 Memory Browser：浏览/搜索所有 Agent 的记忆
📋
Task 任务队列
后端有任务系统：tasks 表、DispatchCenter、AgentPool._collect()。前端只在 Chat 右侧面板看到当前 DAG 的 Agent 状态，看不到全局任务队列。
→ 需要 Task Monitor：全局任务队列视图（所有 Agent 的待处理/执行中/已完成任务）
📂
Workspace 文件系统
每个 Agent 有自己的 workspace 目录，Agent 通过 file_ops 工具读写文件。当前文件操作只在 Chat 的工具调用卡片里一闪而过，用户无法主动浏览/管理这些文件。
→ 需要 File Browser：浏览 Agent 工作空间的文件（可在 Chat 面板内嵌，也可独立页）

建议新增的页面（候选）

#18 Memory Browser

浏览/搜索所有 Agent 的记忆（facts / dreams / summaries / compilations）。FTS5 全文搜索。按 Agent 过滤、按时间排序。可手动添加/编辑/删除记忆。

新增页面 后端已有 API

#19 Task Monitor

全局任务队列视图。所有 Agent 的 pending / running / done / failed 任务列表。支持按 Agent / 场景 / 状态过滤。可取消/重试任务。

新增页面 后端已有 API

#20 File Browser

浏览 Agent 工作空间的文件树。文件预览（代码高亮/Markdown/图片）。可创建/编辑/删除文件。嵌入式（Chat 面板）或独立页面。

新增/嵌入式 需确认 API

边界：以下能力可能不需要独立页面

🔌 Plugin 管理 — 插件系统（plugins/ 目录）目前无 UI。但插件数量少，可暂时放在 Settings 里，不必独立页面。
⏰ Cron 任务管理 — ScheduleModal（488行）已在 Chat 中覆盖 cron 的 CRUD，功能完整。暂不需要独立页面。
📊 系统监控 — CPU/内存/连接数等运维指标。对自托管场景有用但非核心体验。优先度低，可后续迭代。
📝 审计日志 — 多用户操作记录。对团队协作有价值但优先度低于核心交互。先记录需求，后续迭代。
🔗 API 文档 / Developer 页 — 面向外部开发者。当前项目阶段用户是直接操作 UI 的团队管理者，API 文档页优先度低。
