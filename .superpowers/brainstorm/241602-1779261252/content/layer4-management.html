管理体验的四个核心痛点

1

创建流程过于表单化

新建 Agent / Scene 目前要走表单填写（名称、角色、prompt、工具选择...）。在 AI 时代，应该可以通过对话自然语言创建。「我想创建一个擅长代码审查的 Agent」→ 自动生成配置。

2

Agent-Scene-KB 的关系不可见

哪些 Agent 属于哪些 Scene？Scene 用了哪些 Knowledge Base？当前需要跳转多个页面才能看清关系。缺乏关系图谱可视化。

3

缺乏全局状态总览

所有 Agent 的运行状态、最近活动、待处理任务量——没有一个地方能纵览全局。Dashboard 本应做这个，但目前是空的。

4

配置即黑盒，无法预览效果

改了 Agent 的 system prompt 或调整了 Scene 的 context，效果如何？当前需要去 Chat 里实测，缺少配置预览/沙盒测试。

你心目中的 Agent / Scene 管理体验应该更像什么？

A

运维控制台

像 K8s Dashboard —— 状态监控、资源视图、事件流。Agent 是「服务」，Scene 是「环境」。偏理性、偏工程。

B

创作工作室

像 Figma / Notion —— 画布式操作、拖拽组织、所见即所得。Agent 是「角色」，Scene 是「画板」。偏感性、偏创作。

C

对话式管理

一切配置通过自然语言对话完成，像和 CocoCat 聊天一样管理团队。表单只作为 fallback。偏自然、偏 AI-native。
