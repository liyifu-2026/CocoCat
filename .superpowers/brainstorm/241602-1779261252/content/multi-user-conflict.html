⚠ 关键矛盾：Studio 空间隐喻 vs 多账户共享资源

当「工作室布局」撞上「多人共享同一个 Scene」

矛盾拆解

🔴
矛盾 1：工位是谁的？
Studio 隐喻说「Agent 坐在工位上」——好像是固定的。但多用户场景下，Agent 是共享资源，不是某个人的专属。如果我把 Dev Agent 拖到左边，别人看到的也变了吗？
🔴
矛盾 2：Scene 是共享空间
Scene 存储的是「这个场景下有哪些 Agent、哪些 KB」。它是团队级配置，不是个人视图。多人同时在同一个 Scene 里工作时，他们看到的是同一个「工作室」，还是各自的工作室？
🔴
矛盾 3：kb-agent 是固定角色
Coco 和 kb-agent 是系统级固定角色。不是用户「创建」的——它们天生就在。但 Studio 隐喻中新用户看到「空工作室」，然后「添加 Agent」——这和 Coco+kb-agent 已经存在的事实矛盾。
🔴
矛盾 4：布局是数据还是视图？
如果我花时间把工作室排得很漂亮——Dev 在左上、Tester 在右上、资料架在右下——这个布局存在哪里？是存在 Scene 配置里（团队共享），还是存在我的用户偏好里（个人视图）？

退一步：CocoCat 的核心关系到底是什么？

事实：
· 这是一个小团队使用的工具。多人共享 Agent、Scene、KB
· Coco 和 kb-agent 是系统固定角色，天生存在
· Scene = 一组 Agent + KB 的逻辑组合（不是物理空间）
· 多个用户可以同时在同一个 Scene 里工作
· Agent 的「工位」是逻辑概念，不是物理概念

所以核心问题是：「工位」到底是一个逻辑绑定（Scene 配置决定），还是一个视觉排列（用户自己拖动排列）？

三种解决路径

A. 工位 = Scene 配置（团队共享布局）

Scene 的 Agent 列表决定了「工位」。布局由系统自动排列（网格）。所有人看到同一个工作室。修改 Scene 配置 → 所有人看到变化。

Pros

  • 和共享数据一致
  • 无需解决冲突

Cons

  • 丢了「我的工作室」的个人感
  • 工位排列无意义

B. 工位 = 个人视图（各自排列）

Agent 属于 Scene（共享），但每个人可以自己拖动排列工位位置。布局存在用户偏好里，不影响别人。

Pros

  • 保留了个人空间感
  • 拖拽有意义

Cons

  • 数据一致性复杂
  • 「工作室」概念变味：团队工作室还是个人桌面？

C. 放弃空间隐喻，回到信息展示

Dashboard 不是「工作室俯视图」，而是「团队状态面板」。Agent 以卡片/列表展示状态，不强调空间位置。Studio 隐喻只用于理解概念，不在 UI 中物化。

Pros

  • 没有多用户冲突
  • 实现简单

Cons

  • 丢了刚找到的「灵魂」🥲
  • Dashboard 回到卡片堆砌

我倾向 B——但需要确认一个关键前提

B 方案的核心逻辑：
· Scene 定义「这个工作室有哪些 Agent 和 KB」（共享数据）
· 每个人看到的工作室布局是个人视图——Agent 工位排列存在用户偏好里
· 默认布局由系统自动生成（首次进入时），用户可以拖拽调整
· 新加入的 Agent 自动出现在空位
· 切换 Scene = 切换一组 Agent+KB，布局重置为默认或该用户对该 Scene 的已保存排列

这解释了： · 为什么不同人看到的「工作室」可以不一样（个人排列偏好）
· 但 Agent 本身是共享的（数据一致）
· 工位 = 个人视角的「我把这个 Agent 放在这里」，不是物理位置

但代价是：「工作室」从「团队共享空间」变成了「个人仪表盘」。这和你最初说的「小团队使用」会有微妙的语义差异。
