「基地」隐喻下的页面体系重塑

方舟基建概念 CocoCat 映射 页面呈现
基建总览（俯视平面图）Dashboard = 基地总览所有 Agent 工位 + 调度中心 + 知识库的俯视布局。一眼看到谁在忙、谁空闲、任务流向。
制造站 / 贸易站Agent 工位 = 任务执行单元每个 Agent 有自己的「工位」卡片——显示当前任务、进度条、输出。
控制中枢Main AI = 调度中枢DAG 编排、任务分配、团队协作的指挥中心。
宿舍空闲 Agent 列表当前无任务的 Agent 以「休息中」展示，可被唤醒指派任务。
仓库Knowledge Base = 知识仓库存储团队积累的知识资产。
加工站Memory 系统 = 经验加工将对话提炼为记忆/事实，类似「材料加工」。
发电站System Status = 能源状态API 余额、模型可用性、系统资源。
会客室Chat = 会客/协作窗口用户和 AI 团队的对话界面。
基建副手CocoCat (猫) = 基建副手猫猫是整个基地的「管家」，在基地中走动、报告状态、提醒事项。

这个隐喻带来的交互升级

🔗 任务流转可视化 — DAG 任务从 Main AI → Dev → Tester 的流动，在基地俯视图上以连线动画呈现。可以看到「工作」在工位之间传递。
😴 闲置≠无用 — 空闲的 Agent 在「宿舍区」休息，不是冷冰冰的「offline」标签。当任务到来时，它们被「唤醒」走到工位上。
🐱 猫的深度角色化 — 猫不是装饰，是「基建副手」。在基地里走动、停在忙碌的 Agent 旁边查看、叼着完成的任务报告跑向你。
🏗 成长感 — 基地从小变大：初始只有 1 个 Agent 工位 + 猫，逐渐解锁更多工位、知识库书架、调度中心。用户能感受到「团队在成长」。
🎯 Dashboard 终于有灵魂 — 不再是数据卡片堆砌，而是一个有空间感、有生命力的「基地俯视图」。

这改变了全局交互范式——你觉得这个方向值得深入吗？
