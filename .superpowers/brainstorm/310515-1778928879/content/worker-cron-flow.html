设计 Section 6：Worker 调用 & Cron 调度

Resident agent 如何调用 Worker 池 + 定时巡检机制

Resident agent 调用 Worker 池
# kb-agent 需要执行耗时任务时（如 ingest、大量文件处理），
# 不自己扛，而是调用 Worker 池

call_worker(task: str, context: dict) → WorkerResult

# 示例：kb-agent 收到上传文件，触发 ingest
kb-agent → call_worker(
    task="ingest source file {filename} into KB {kb_name}",
    context={"kb": kb_name, "file": path}
)
→ Worker Pool 分配空闲 Worker 执行
→ Worker 调用 IngestPipeline
→ 返回结果给 kb-agent

# Coco 也一样用 call_worker
Coco → call_worker(task="create React component...", ...)
→ Worker Pool 执行
→ 返回结果
Cron 定时巡检
# 内置 CronTaskRunner，与现有 TaskWorker 合并

class CronTaskRunner:
    """每个 Resident agent 可注册 cron 表达式，Runner 触发时直接调用 agent"""

    def tick(self):
        for resident in self.residents:
            for job in resident.cron_jobs:
                if job.is_due():
                    resident.handle_cron(job)  # 直接调用，不进 tasks 表

# kb-agent 的 cron 配置
cron:
  - name: lint
    schedule: "@daily"        # 每天健康检查
  - name: dedup
    schedule: "@weekly"       # 每周去重
  - name: overview
    schedule: "@weekly"       # 每周刷新概览
完整数据流
用户上传文件到 /api/knowledge/{kb}/upload
  → 保存到 raw/sources/
  → 推送事件给 kb-agent: {event: "source_uploaded", file: "..."}
  → kb-agent 评估：是简单文件 → call_worker(ingest)
                    是复杂材料 → 亲自处理（加载 skill，拆解，注入）

用户在前端和小窗对话
  → HTTP/WS 直接发给 kb-agent
  → kb-agent 自行决定：自己回答 / call_worker / 调用 KB 工具

Cron 触发
  → CronTaskRunner tick → kb-agent.handle_cron("lint")
  → kb-agent 调用 run_lint 工具 → 有问题则 call_worker 修复

Worker agent 需要查 KB
  → 调用 search_kb / read_wiki（只读）→ 获取 KB 知识辅助决策
