设计 Section 3：KBService 服务层

把散落在 ingest/*.py 的能力统一封装成可测试的纯函数服务

class KBService:
    """纯函数服务层，不依赖 LLM、不依赖 HTTP。所有 KB 操作的统一入口"""

    # ── 查询（供所有人） ──
    search(kb_name, query, limit=20) → list[SearchResult]
        # 全文本搜索 wiki/*.md，返回标题+匹配片段

    read(kb_name, type, slug) → WikiPage | None
        # 读取单个 wiki 页面（含内容+frontmatter）

    list_pages(kb_name) → dict[list[str], list[str]]
        # {entities: [...], concepts: [...]}

    get_graph(kb_name) → GraphResult
        # {nodes, links, insights: {connections, gaps, bridges}}

    # ── 写入（仅 kb-agent） ──
    write_page(kb_name, type, slug, content, frontmatter) → None
        # 创建/覆盖 wiki 页面，自动更新 index.md + log.md

    cascade_delete(kb_name, source_filename) → CascadeResult
        # 删除源文件 → 清理关联页面 → 更新 index

    # ── 维护（仅 kb-agent） ──
    run_dedup(kb_name, llm) → DedupResult
        # {merged: int, removed: list[str], log: str}

    run_lint(kb_name) → LintResult
        # {orphans, broken_links, missing_frontmatter, ...}

    gen_overview(kb_name, llm) → str
        # 返回生成的 overview markdown 文本，写入 overview.md

    # ── 注入（给 agent 的 system prompt） ──
    get_overview_context(kb_names) → str
        # 替代现有 load_kb_overview()，整合 overview.md + index.md
与现有代码的关系
  • IngestPipeline → KBService 不接管 ingest，保留现有 Worker 触发
  • DedupPipeline → KBService.run_dedup 封装
  • lint_kb() → KBService.run_lint 封装
  • update_overview() → KBService.gen_overview 封装
  • KnowledgeGraph → KBService.get_graph 封装
  • cascade_delete_source → KBService.cascade_delete 封装
  • load_kb_overview() → KBService.get_overview_context 替代
设计原则
  • 大部分方法纯文件 I/O，无副作用
  • LLM 作为参数传入（run_dedup、gen_overview）
  • 可独立单元测试（mock LLM 即可）
  • 不做权限校验——调用方（agent tool）负责
  • 文件位置：cococat/kb/service.py
